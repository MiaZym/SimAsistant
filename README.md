# SimAssistant

Прототип сервиса работы с LLM: чат, анализ больших документов, разбор звонков.
Интерфейс на Streamlit, один docker-контейнер, провайдер моделей переключается в UI —
от локального Ollama до любого OpenAI-compatible API.

У прототипа нет авторизации и долговременного хранения сессий — состояние живёт
в памяти процесса. Это осознанная простота: поверх всегда можно
поставить reverse-proxy с аутентификацией или своё хранилище, архитектура не мешает.
В таком виде проект удобно взять, например, в сеть, где до моделей есть только API:
поднимаешь одним контейнером и получаешь UI для диалога с внутренними и внешними
моделями, их тестирования и первой автоматизации рутины.

Статус: рабочий прототип. Код обкатан на реальных документах и записях звонков,
работает в реальной среде и ежедневно приносит пользу; при этом API и структура
ещё могут меняться.

## Возможности

Чат со стримингом:
- вложения PDF/DOCX/XLSX/TXT прямо из поля ввода (Streamlit >= 1.44);
- остановка генерации по кнопке — уже написанный кусок ответа сохраняется;
- повтор последнего ответа кнопкой под сообщением;
- экспорт истории в PDF, метаданные ответа (время, примерное число токенов);
- блоки рассуждения моделей (`...`) выносятся в сворачиваемую секцию;
- светлая и тёмная тема.

Анализ больших документов (map-reduce: план -> чанки -> накопительное резюме -> отчёт):
- PDF, DOCX, XLSX, TXT, лимит 500 МБ на файл;
- шаблоны типовых задач (exec summary, риски, метрики);
- стратегии дробления: по диалогам/заголовкам, regex-разделителю, абзацам, символам, с overlap;
- автосжатие промежуточного резюме, когда оно разрастается;
- подсказка по размеру чанка исходя из контекстного окна модели;
- экспорт отчёта в DOCX и Markdown; результат живёт в session_state
  и не теряется при перезапуске скрипта.

Анализ звонков: WAV -> транскрибация через внешний ASR-сервис -> отчёт
(группы причин обращений, referral-пары, эскалации). Пакетная обработка.

Отдельная вкладка пакетной транскрибации WAV в единый .docx.

## Архитектура

```
        ┌─────────────────────────── UI (Streamlit) ───────────────────────────┐
        │  Чат   │   Анализ документов   │   Анализ звонков   │   Транскрибация  │
        └────┬──────────────┬──────────────────┬────────────────────┬──────────┘
             │              │                  │                    │
             │        document_extract   transcribe_client ──► внешний ASR-сервис
             │              │
             ▼              ▼
        LLMClient ◄──GenerationParams      run_chunked_analysis (analyzer.py)
       (ollama / openai-compatible)         plan → chunks → notes+summary → report
             │                                      ▲
             ▼                                      │
   LLM-сервер (Ollama / vLLM / custom API)   chunking.py (smart/separator/paragraphs/chars)
```

Поток анализа: загрузка -> извлечение текста -> план по сэмплу -> дробление ->
цикл по чанкам (заметки + резюме) -> финальный отчёт со стримингом -> экспорт.

Каждая вкладка обёрнута в `st.fragment`: нажатие кнопки внутри вкладки
не перезапускает всё приложение.

UI сделан нативными виджетами Streamlit; тёмная тема — CSS-оверлей поверх
нативной светлой (`src/styles.py`). Никаких сторонних фронтенд-фреймворков.

## Требования

- Docker и Docker Compose (или Python 3.11+ без Docker);
- LLM-сервер: Ollama, vLLM или любой OpenAI-compatible API;
- опционально: HTTP-сервис транскрибации для вкладок «Звонки» и «Транскрибация».

## Быстрый старт

```bash
ollama run qwen2.5:7b          # или другой LLM-сервер
cp .env.example .env           # для локального запуска достаточно дефолтов
docker compose up --build      # http://localhost:8501
```

Подробности, типовые проблемы и сборка за прокси — [docs/QUICKSTART.md](docs/QUICKSTART.md).

## Конфигурация

Все переменные в `.env` (шаблон — `.env.example`):

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `DEFAULT_OLLAMA_URL` | URL Ollama-сервера | `http://host.docker.internal:11434` |
| `DEFAULT_VLLM_URL` | URL vLLM-сервера | `http://host.docker.internal:8000` |
| `VLLM_API_KEY` | Ключ для vLLM (если нужен) | пусто |
| `VLLM_EXTRA_HEADERS` | Доп. заголовки для vLLM, JSON-строка | пусто |
| `DEFAULT_CUSTOM_URL` | Base URL OpenAI-compatible API (без `/v1`) | `https://api.openai.com` |
| `DEFAULT_CUSTOM_API_KEY` | API-ключ внешнего провайдера (можно задать в UI) | пусто |
| `DEFAULT_CUSTOM_MODELS` | Fallback-список моделей через запятую | пусто |
| `DEFAULT_CUSTOM_EXTRA_HEADERS` | Доп. заголовки для custom API, JSON-строка | пусто |
| `TRANSCRIBE_URL` | URL сервиса транскрибации | `http://host.docker.internal:8077/api/v1/transcribe` |
| `TRANSCRIBE_FILE_FIELD` | Имя multipart-поля для файла | `file` |
| `LLM_TIMEOUT_SEC` | Таймаут запросов к LLM | `600` |
| `HOST_PORT` | Порт приложения на хосте | `8501` |
| `BASE_IMAGE` | Базовый Docker-образ (для внутреннего зеркала) | `python:3.11-slim` |
| `REQUESTS_CA_BUNDLE` | CA-бандл для self-signed TLS внутри периметра | пусто (certifi) |

Лимит загрузки файлов — 500 МБ (`src/.streamlit/config.toml`).
Экспорт чата в PDF использует системный Unicode-шрифт (Noto/DejaVu) —
в docker-образе они есть, при локальном запуске без них кириллица в PDF может бититься.

## Сценарии

- Большой PDF-отчёт: вкладка «Документы», шаблон «exec summary», стратегия smart, экспорт в Word.
- Пакет текстовых транскриптов звонков: «Документы», режим «Всплеск обращений» —
  диалоги разделяются строками `=====` / `-----` / `_____`.
- Записи звонков: «Звонки» — WAV, транскрибация, отчёт с причинами обращений.
- Нужен только текст: «Транскрибация» — WAV на вход, один .docx на выходе.

## Структура

```
src/
  app.py                  UI: 4 вкладки на st.fragment
  analyzer.py             map-reduce конвейер анализа
  chunking.py             стратегии дробления текста
  document_extractors.py  извлечение текста: PDF/DOCX/XLSX/TXT
  exporters.py            экспорт в DOCX/Markdown, чат в PDF (fpdf2)
  llm_client.py           клиенты Ollama / OpenAI-compatible, параметры генерации
  transcribe_client.py    клиент ASR-сервиса
  prompts.py              промпты план/чанк/финал/сжатие, парсеры маркеров
  config.py               настройки из .env (pydantic-settings)
  styles.py               светлая/тёмная CSS-темы
  utils.py                мелочи без зависимости от streamlit
  exceptions.py           общие исключения
tests/                    pytest, включая дым-тесты UI через streamlit AppTest
docs/                     быстрый старт и заметки о провайдерах
.github/workflows/ci.yml  ruff + pytest
```

## Разработка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install pytest ruff

streamlit run src/app.py     # запуск без Docker
pytest                       # тесты
ruff check src tests         # линтер
```

Логика, которую можно проверить без UI, вынесена из `app.py` в обычные модули
и покрыта pytest; UI проверяется дым-тестами через `streamlit.testing.v1.AppTest`.

Перед выкладкой в публичный git: не коммитить `.env`; если `poetry.lock`
собран от приватного index — перегенерировать его и убрать приватные
`[[tool.poetry.source]]` из `pyproject.toml`.
