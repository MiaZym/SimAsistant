# Безопасность

## Модель безопасности прототипа

Прототип сознательно сделан простым: одно приложение в одном контейнере,
без авторизации и без хранения состояний между сессиями. В рамках этого
сценария приняты обычные меры предосторожности:

- ключи API живут только в `.env` (в `.gitignore`) или вводятся в UI полем-паролем,
  в логи и в URL не попадают;
- приложение обращается наружу только к эндпоинтам, которые явно задал
  пользователь (LLM/ASR URL), и только с ключами минимальных прав;
- извлечение текста из документов выполняется локально в контейнере
  (pypdf, python-docx, openpyxl), файлы никуда не отправляются;
- всё состояние — в памяти процесса: после остановки контейнера не остаётся ничего.

Чего намеренно нет и что добавляется поверх при необходимости:
аутентификация, разграничение доступа, долговременное хранилище сессий/историй,
изолированные workspace. Типовой вариант для такого случая — reverse-proxy
с аутентификацией перед контейнером; архитектура приложения этому не мешает.
Само приложение в публичный интернет без прослойки выставлять не стоит.

## Сообщения об уязвимостях

Приветствуются сообщения и рекомендации! Уязвимость лучше прислать приватным
security-адвайзом на GitHub (Security → Report a vulnerability), детали публично
не публиковать. Идеи по улучшению безопасности — просто в Issues.
