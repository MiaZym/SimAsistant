# Быстрый старт

## Предварительные требования

- Docker и Docker Compose
- LLM сервер (Ollama или vLLM)
- Опционально: сервис транскрибации для обработки аудио

## Шаг 1: Установка и запуск LLM сервера

### Вариант A: Ollama (рекомендуется)

1. Установите Ollama с [официального сайта](https://ollama.ai/)

2. Запустите модель:
```bash
ollama run llama3.2
# или другую модель:
# ollama run llama3.2:1b
# ollama run qwen2.5:7b
```

### Вариант B: vLLM

```bash
# Установите vLLM
pip install vllm

# Запустите сервер
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.2-3B-Instruct \
  --port 8000
```

## Шаг 2: Настройка проекта

### Клонируйте репозиторий

```bash
git clone https://github.com/YOUR_USERNAME/llm-document-analyzer.git
cd llm-document-analyzer
```

### Настройте переменные окружения

```bash
# Скопируйте пример конфигурации
cp .env.example .env

# Отредактируйте .env при необходимости (опционально)
nano .env  # или любой другой редактор
```

Содержимое `.env` по умолчанию:
```env
TRANSCRIBE_URL=http://host.docker.internal:8077/api/v1/transcribe
TRANSCRIBE_FILE_FIELD=file

OLLAMA_URL=http://host.docker.internal:11434
VLLM_URL=http://host.docker.internal:8000

LLM_TIMEOUT_SEC=600
```

## Шаг 3: Запуск сервиса

### Запуск через Docker Compose (рекомендуется)

```bash
# Соберите и запустите контейнер
docker compose up --build

# Или в фоновом режиме
docker compose up -d --build
```

### Запуск без Docker (для разработки)

```bash
# Перейдите в папку с кодом
cd src

# Установите зависимости
pip install -r requirements.txt

# Настройте переменные окружения
export OLLAMA_URL=http://localhost:11434
export VLLM_URL=http://localhost:8000

# Запустите приложение
streamlit run app.py
```

## Шаг 4: Откройте в браузере

Перейдите на:
```
http://localhost:8501
```

## Использование

### 1. Чат с LLM

1. На главной странице выберите провайдера (Ollama/vLLM)
2. Выберите модель из списка
3. Настройте системный промпт (опционально)
4. Начните диалог!

### 2. Анализ документа

1. Перейдите на вкладку **"Анализ документа"**
2. Загрузите файл (PDF, DOCX, XLSX, TXT)
3. Настройте параметры:
   - **Режим анализа**: выберите "Общий" или "Всплеск обращений"
   - **Системный промпт**: роль и контекст для модели
   - **Финальный запрос**: что нужно получить в итоге
   - **Дробление**: размер чанка, overlap, стратегия
4. Нажмите **"Старт анализа"**
5. Следите за прогрессом в реальном времени
6. Экспортируйте результат в `.md`

**Пример настроек для анализа PDF отчёта:**
- Режим: Общий анализ
- Размер чанка: 8000 символов
- Overlap: 200 символов
- Стратегия: По абзацам
- Финальный запрос: "Составь подробное резюме с ключевыми выводами и рекомендациями"

**Пример настроек для транскриптов звонков:**
- Режим: Всплеск обращений
- Размер чанка: 12000 символов
- Overlap: 500 символов
- Стратегия: По разделителю (паттерн `_{3,}|-{3,}|={3,}`)
- Финальный запрос: "Выяви основные причины всплеска обращений и дай рекомендации"

### 3. Анализ звонков (с транскрибацией)

1. Перейдите на вкладку **"Анализ звонков"**
2. Загрузите несколько WAV файлов
3. Файлы будут автоматически транскрибированы
4. Настройте параметры анализа (как в п.2)
5. Получите итоговый отчёт

**Примечание:** Для этой функции требуется запущенный сервис транскрибации.

### Анализ большого PDF отчёта

Задача: Проанализировать 100-страничный отчёт

2. Выберите режим "Общий анализ"
3. Финальный запрос: "Составь executive summary с ключевыми метриками, выводами и рекомендациями"

```
Задача: Найти причины всплеска обращений из 50 диалогов

1. Подготовьте файл с транскриптами (разделитель =====)
2. Загрузите в "Анализ документа"
3. Выберите режим "Всплеск обращений"
4. Стратегия дробления: "По разделителю" (паттерн: _{3,}|-{3,}|={3,})
5. Финальный запрос: "Сгруппируй причины обращений и выяви основные проблемы"
6. Получите структурированный отчёт с группировкой
```

### Обработка аудиозвонков

```
Задача: Транскрибировать и проанализировать 20 звонков

1. Перейдите в "Анализ звонков"
2. Загрузите WAV файлы (до 200MB каждый)
3. Дождитесь транскрибации
4. Настройте анализ (режим "Всплеск обращений")
5. Получите отчёт с причинами обращений
```

## Решение проблем

### LLM сервер недоступен

**Проблема:** "Connection refused" или "Failed to fetch models"

**Решение:**
```bash
# Проверьте, что Ollama запущен
ollama list

# Проверьте доступность API
curl http://localhost:11434/api/tags

# Для vLLM:
curl http://localhost:8000/v1/models
```

### Docker контейнер не может подключиться к хосту

**Проблема:** Сервис в Docker не видит Ollama на хосте

**Решение:**
- В файле `.env` используйте `host.docker.internal` вместо `localhost`
- Уже настроено по умолчанию в `.env.example`
- Для Linux дополнительная настройка в `docker-compose.yml` уже добавлена

### Ошибки при извлечении текста из документа

**Проблема:** "Failed to extract text" или "Unsupported format"

**Решение:**
- Проверьте формат файла (поддерживаются: PDF, DOCX, XLSX, TXT)
- Для старых DOC файлов конвертируйте в DOCX
- Убедитесь, что файл не защищён паролем
- Проверьте, что файл не повреждён

### Медленная работа

**Решение:**
- Используйте меньшую модель (например, llama3.2:1b вместо llama3.2:70b)
- Увеличьте размер чанка (меньше запросов к модели)
- Используйте GPU для ускорения inference
- Для Ollama: установите переменную `OLLAMA_NUM_PARALLEL=2`

### Сервис транскрибации недоступен

**Проблема:** "Transcription failed"

**Решение:**
- Эта функция опциональна, используйте для звонков только если есть сервис транскрибации
- Для анализа уже готовых транскриптов используйте "Анализ документа"

## Дополнительные настройки

### Изменение порта

Отредактируйте `docker-compose.yml`:
```yaml
ports:
  - "8080:8501"  # вместо 8501:8501
```

### Увеличение таймаута

В файле `.env`:
```env
LLM_TIMEOUT_SEC=1200  # 20 минут вместо 10
```

### Использование нескольких GPU

Отредактируйте `docker-compose.yml`:
```yaml
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: all
          capabilities: [gpu]
```
